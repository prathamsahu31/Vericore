You are reading a government Request for Proposal to build an eligibility
checklist for a procurement officer.

Find the pre-qualification / eligibility criteria section and the technical
qualification section. In this kind of document they are numbered sections
containing a table whose columns are typically:

    SN | Basic Criteria | Detailed Criteria | Applicability | Documents Required

Return one entry per table ROW — one per numbered criterion. Do not merge rows,
and do not split one row into several. Each requirement must be understandable
on its own to a non-technical procurement officer reading the checklist.

Return JSON of exactly this shape:

{{
  "requirements": [
    {{
      "code": "REQ-001",
      "name": "<the Basic Criteria cell, short>",
      "category": "<one of: financial_eligibility, experience, technical, statutory, declarations, bid_security>",
      "raw_clause": "<the Detailed Criteria cell, verbatim>",
      "normalized_clause": "<the same condition in one plain sentence>",
      "condition": <see below, or null>,
      "mandatory": true,
      "weight": 0,
      "applicability_scope": "<lead_only | any_member | all_members | aggregate>",
      "accepts_document_types": ["<from the vocabulary below>"],
      "required_fields": ["<field names from the document schemas that this requirement actually checks>"],
      "external_check": null,
      "source_page": <page number the row appears on>,
      "source_clause_ref": "<the section or SN number, e.g. '6.1 row 3'>",
      "confidence": <0.0-1.0>
    }}
  ]
}}

APPLICABILITY — read the Applicability column, do not assume:
  "Sole Bidder or prime bidder of the Consortium"    -> "lead_only"
  "Sole Bidder or all members in the consortium"     -> "all_members"
  "Sole Bidder and each consortium member"           -> "all_members"
  "Sole Bidder or any consortium member"             -> "any_member"
  combined / aggregate turnover permitted            -> "aggregate"
If the column is absent or you cannot tell, use "lead_only" and lower your
confidence. The stricter reading is the safe error.

normalized_clause — one plain-English sentence that a non-technical officer
can read and immediately understand. Always include the figure and period when
present. Examples:
  "Average annual turnover of at least Rs. 100 crore over the last 3 financial years."
  "At least 1 similar work of value not less than Rs. 40 crore completed in the last 7 years."
  "Valid and active GST registration certificate in the name of the bidding entity."

CONDITION — include this object ONLY when the criterion states a figure, a
date, or a period you could check arithmetically. Otherwise use null.
  {{"field": "average_annual_turnover", "operator": ">=", "threshold": <integer rupees>,
    "unit": "INR", "period_years": <n>}}
  {{"field": "order_value", "operator": ">=", "threshold": <integer rupees>,
    "unit": "INR", "min_count": <n>, "within_years": <n>}}
  {{"field": "incorporation_date", "operator": "min_years_before_due_date", "threshold": <n>}}
  {{"field": "net_worth", "operator": ">=", "threshold": <integer rupees>, "unit": "INR"}}
  {{"field": "rated_throughput_tpd", "operator": ">=", "threshold": <integer>, "unit": "TPD"}}
  {{"field": "local_content_percent", "operator": ">=", "threshold": <integer>, "unit": "percent"}}
  {{"field": "emd_amount", "operator": ">=", "threshold": <integer rupees>, "unit": "INR"}}
  {{"field": "valid_until", "operator": "not_expired_at_due_date"}}

Rupee figures: convert to plain integers. "INR 500 Crore" is 5000000000.
"Rs. 70 Crores" is 700000000. Use Indian numbering faithfully: "Rs. 62,00,00,000"
is 620000000 (sixty-two crore), NOT 62000000. Always count the commas.
If a criterion offers ALTERNATIVE thresholds
(one project of 70 Cr OR two of 40 Cr OR three of 30 Cr), use the option with
the LOWEST min_count, and describe the alternatives in normalized_clause.

accepts_document_types — use ONLY these values:
{allowed_types}
Choose from the Documents Required column. Use an empty list if it names no
document type you recognise.

required_fields — the specific field names (from the document schemas) that
must be present for this requirement to be judged. Examples:
  turnover requirement      -> ["turnover_fy1", "turnover_fy2", "turnover_fy3"]
  GST registration          -> ["gstin", "legal_name"]
  PAN check                 -> ["pan", "legal_name"]
  incorporation / age       -> ["incorporation_date", "legal_name"]
  work order / experience   -> ["order_value", "completion_date", "client_name"]
  ISO / OEM / EPFO validity -> ["valid_until"]
  technical datasheet       -> ["rated_throughput_tpd"] or ["material_of_construction"]
  declaration               -> ["declaration_signed"]
If the requirement is only that a document exists (no specific field check),
use an empty list. Never invent a field name outside the schemas.

mandatory — true if the detailed criteria says "shall", "must", "required" or
the Mandatory column says Yes. False if it says "where the bidder claims",
"if applicable", or Mandatory is No/Conditional. Weight is 0 for most rows;
only copy the Weight column value if one is printed in the table.

Do NOT invent criteria. If the section is not present in this document, return
an empty requirements list. Reporting nothing is correct and useful; inventing
a plausible-looking checklist would silently corrupt every verdict formed
against it.
